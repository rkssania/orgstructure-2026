# Сестринский блок: логика наряда и графика

Описание для разработчиков. Код — `sestry.html` (один файл, без сборки). Вход — карточка «Сестринский блок» в `funkcii.html`.

## Кто и что

- Пользователь — руководитель сестринской службы филиала (КРГ, УК, Астана). Каждое утро формирует наряд на день и ведёт график смен на месяц.
- Группы персонала:
  - `mc` — медсёстры-универсалы (бывшие МС КС, ДС, трансфузионного кабинета);
  - `pit` — медсёстры ПИТ, отдельная группа со своими постами;
  - `san` — санитарки (уход и клининг объединены).
- Не входят в наряд: медсестра инфекционного контроля (в графике отдельной строкой, 5/2 по 8 ч) и медсёстры кабинета разведения (перешли в фармблок).
- Список сотрудников — снимок новой оргструктуры, вшит в страницу (`const STAFF`). Добавить или убрать человека можно в разделе «Сотрудники и допуски», это хранится в настройках филиала.

## Хранение

Общая база «Функционала» (Supabase, таблица `items`: `coll`, `id`, `data`, `by_email`, `at`). Доступ — та же авторизация и `is_allowed`, что у `funkcii.html`. Адаптер в начале `sestry.html` отдаёт модулю интерфейс `db.doc(path).get/set` и `db.collection(name).onSnapshot`. Подписка работает опросом раз в 15 секунд.

| coll | id | что внутри |
|---|---|---|
| `sb_cfg` | филиал (`КРГ`) | настройки филиала: зоны, допуски, схема, учётный период, лимит смен подряд, «без ночей», добавленные и убранные сотрудники |
| `sb_mon` | `КРГ_2026-11` | месяц: правки графика по людям и наряды по дням |
| `sb_reviews` | email | оценки функционала старшими медсёстрами (вкладка «Функционал») |

### `sb_cfg/{филиал}`

```js
{
  zv: 3,                  // версия модели зон; при меньшей зоны и время смен сбрасываются на умолчание
  scheme: 'dnvv',         // шаблон графика: dnvv | sep | free
  ds:'08:00', de:'18:00', ns:'18:00', ne:'08:00', brk:0,   // время смены по умолчанию (если зона без часов)
  maxRun: 5,              // не больше N смен подряд
  period: 'm' | 'q',      // учётный период для баланса часов: месяц или квартал
  zones: { mc:{day:[Zone], night:[Zone]}, pit:{…}, san:{…} },
  dop:    { [pid]: { tr:true, man:false, post:true, ds:true, pit:true, st:true, cl:true, care:true } },
  nonight:{ [pid]: 1 },   // не ставить в ночь
  extra:  { mc:[ФИО], pit:[], san:[] },   // добавленные вручную
  gone:   { [pid]: 1 }    // убраны из графика
}
Zone = { id, n:'Пост 1', k:'post' /*допуск*/, s:'08:00' /*начало*/, h:10 /*часов к оплате*/,
         wd:1 /*только будни*/, opt:1 /*добавляется кнопкой*/, sit:1 /*открывается с причиной*/ }
```

`pid` — хеш от ФИО (`pid(n)`), так что ФИО — ключ человека.

### `sb_mon/{филиал}_{ГГГГ-ММ}`

```js
{
  norm: 168,              // норма месяца, если руководитель поправил вручную
  p: { [pid]: { b:'А',    // бригада (шаблон)
                x:{ '19':'Д' } } },   // ручные правки дня поверх шаблона
  nar: { '19': {
      mc_day:  { [zoneId]: pid },     // кто в какой зоне
      mc_night:{ … }, pit_day:{…}, pit_night:{…}, san_day:{…}, san_night:{…},
      st_day: pid, st_night: pid, st_pit_day: pid, st_pit_night: pid,   // старшая по смене (= пост 1)
      open: { [zoneId]: 'Агранулоцитоз' | '+' },   // открытые ситуативные/дополнительные зоны
      ok: { at:'19.11, 08:12', by:'email' }        // наряд утверждён
  } }
}
```

Коды дня в графике: `Д` день, `Н` ночь, `8` восьмичасовая, `В` выходной, `О` отпуск, `Б` больничный, `А` без содержания.

## Зоны по умолчанию (КРГ, УК)

| Группа | Зона | Начало | Часы | Когда |
|---|---|---|---|---|
| mc | Трансфузионный кабинет · МС 1 | 08:00 | 8 | будни |
| mc | Трансфузионный кабинет · МС 2 | 08:00 | 12 | каждый день |
| mc | Пост 1, Пост 2 | 08:00 / 18:00 | 10 днём / 14 ночью | каждый день |
| mc | Пост 3 | 08:00 / 18:00 | 10 / 14 | по причине (`sit`) |
| mc | Дневной стационар · МС 1, МС 2 | 08:00 | 8 | будни |
| mc | Манипуляционный кабинет | 08:00 | 8 | будни |
| pit | ПИТ, пост 1–2 (+ пост 3 по причине) | 08:00 / 18:00 | 10 / 14 | каждый день |
| san | Уход 1–3, Клининг 1–3 | 08:00 / 18:00 | 10 / 14 | первая каждый день, вторая и третья кнопкой (`opt`) |

Астана — урезанный набор (ДС, манипуляционный, остальное кнопкой). Всё редактируется в «Настройках».

Старшая по смене — всегда тот, кто на посту 1 (`p1`/`p1n`, в ПИТ `pit1`/`pit1n`). Отдельно не выбирается.

## Часы и баланс

- Часы дня (`dayHrs`): если человек стоит в зоне наряда — `zone.h`; иначе по коду графика (`Д` и `Н` — по времени смен из настроек, `8` — 8).
- Баланс (`bal`): `ставка × (норма месяца − 8 × рабочие дни отпуска и больничного)`.
- Норма месяца по умолчанию — 8 ч × рабочие дни без праздников РК (`HOL`). Руководитель может поправить.
- Учётный период `q` — баланс и часы суммируются с начала квартала по текущий месяц (`periodStats`).

## Правила ТК РК — `rule(p, d, sh, zone)`

Каждое назначение (ручное, автоматическое, «Как вчера», замена) проходит через `rule`. Пустая строка — можно; иначе — причина, и назначение не делается.

1. Отпуск, больничный, без содержания — нельзя.
2. Отметка «без ночей» — нельзя в ночную зону.
3. Уже стоит в другой смене этой даты — нельзя: две смены подряд (ст. 73 ТК РК).
4. Отдых между сменами не меньше 12 ч. Считается по реальному времени: конец смены предыдущего дня → начало этой зоны и конец этой зоны → начало смены следующего дня (`span`).
5. Не больше `maxRun` смен подряд (по умолчанию 5), чтобы был выходной в неделю.
6. Часы: если назначение добавляет часы сверх уже запланированных и итог выше баланса больше чем на 12 ч (лимит сверхурочных в месяц) — нельзя. Запланированную по графику смену правило 6 не блокирует.

В графике месяца нарушения отдыха подсвечиваются красной рамкой по тому же расчёту `span`. Правки клеток графика не блокируются: это план, блокировка — в наряде.

Следствие 14-часовых ночей: две ночи подряд невозможны (отдых 10 ч). Поэтому для КРГ и УК шаблон по умолчанию — `dnvv` (день, ночь, отсыпной, выходной).

## Автоматическое формирование — `autoAssign(d, sh, grp)`

1. Наряд смены очищается.
2. Зоны сортируются: сначала пост 1 (старшая), потом зоны с самым редким допуском.
3. Для каждой зоны `pickFor` берёт кандидатов: не ИК, ещё не занят в этой смене, есть допуск, `rule` пуст.
4. Счёт кандидата (меньше — лучше):
   - `0`, если по графику в этой смене, иначе `500`;
   - `+ (часы − баланс)` за период: у кого больше часов осталось, тот выше;
   - `+ 3 × сколько раз в этом месяце стоял в этой зоне`;
   - `+ 60 × сколько последних дней подряд стоял в этой зоне` (правило 2–3 смен подряд в одном кабинете);
   - `+ 1000` для поста 1, если нет допуска «Старшая по смене».
5. Поставленному вне графика автоматически ставится `Д`/`Н` в график (`putIn` → `setCode`).
6. Если кандидата нет — зона остаётся пустой, руководитель видит «пустых зон: N».

## Остальные действия наряда

- **Как вчера** (`copyPrev`) — переносит вчерашние назначения той же смены и открытые зоны. Кого нельзя по `rule`, пропускает и называет в сообщении.
- **Не вышла** (кнопка ⊘, `notCame`) — ставит человеку `Б` на этот день, снимает с зоны и подбирает замену через `pickFor`.
- **Открыть зону** (`openZone`) — `opt` открывается сразу, `sit` спрашивает причину (затяжелел, агранулоцитоз, поступление в ночь, другое). Сразу пробует поставить человека.
- **Доступны сейчас** — чипы людей, которых можно поставить в эту смену. Нажать имя, затем «Сюда» у зоны (удобно с телефона).
- **Утвердить наряд** — пишет `ok: {at, by}`. Любое изменение дня после этого снимает утверждение и предупреждает.
- **В WhatsApp** — копирует текст наряда с часами и старшей.
- **Сводка** — по месяцу: сколько раз каждый стоял в каждой зоне, сколько раз был старшей, часы и баланс.

## Открытые вопросы

- Ночные смены 14 ч длиннее 12 ч, допустимых по разъяснениям к ТК РК для сменной работы. Нужно решение юриста; альтернатива — 12/12 (08:00–20:00 / 20:00–08:00), меняется в настройках зон.
- Опрос раз в 15 секунд: при одновременной правке одного дня двумя людьми выигрывает последний сохранивший (документ месяца пишется целиком).
- Список сотрудников вшит снимком. При смене оргструктуры нужно обновить `STAFF` в `sestry.html`.
- Праздники РК в `HOL` — фиксированные даты, без переносов и плавающих праздников.
